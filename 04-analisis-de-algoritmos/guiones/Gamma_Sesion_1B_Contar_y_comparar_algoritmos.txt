EL PROBLEMA

Dado un entero n ≥ 1, calcular:

S(n) = 1 + 2 + 3 + … + n

Entrada: n.

Salida: el valor exacto de S(n).

Antes de diseñar, calculen S(1), S(2), S(5) y S(10). Conserven estos casos para detectar errores de límites, inicialización y fórmula.

ESTRATEGIA A | RECORRIDO

ALGORITMO suma_iterativa(n)
  total ← 0
  PARA i ← 1 HASTA n
    total ← total + i
  FIN PARA
  devolver total
FIN

Identifiquen entrada, acumulador, condición de repetición y salida.

ESTRATEGIA B | EMPAREJAR EXTREMOS

Observa:

1 + n = n + 1

2 + (n−1) = n + 1

3 + (n−2) = n + 1

Cada pareja tiene la misma suma. La cantidad de parejas depende de si n es par o impar.

---

CASOS PAR E IMPAR

Para n=10 hay n/2 parejas, cada una suma n+1:

(1+10)+(2+9)+…+(5+6)

Para n=9 hay piso(n/2) parejas y queda (n+1)/2:

(1+9)+(2+8)+(3+7)+(4+6)+5

Construyan ambas trazas e indiquen cómo tratar el valor central.

---

PSEUDOCÓDIGO DE EMPAREJAMIENTO

ALGORITMO suma_pares(n)
  total ← 0
  PARA i ← 1 HASTA piso(n/2)
    total ← total + i + (n-i+1)
  FIN PARA
  SI n es impar
    total ← total + (n+1)/2
  devolver total
FIN

---

CONFRONTAR: MENOS ITERACIONES NO SIEMPRE ES MENOS TRABAJO

El emparejamiento usa aproximadamente n/2 iteraciones, pero su cuerpo realiza más operaciones que el recorrido simple.

Comparen bajo dos modelos:

1. contar únicamente iteraciones;
2. contar sumas y restas.

¿La conclusión permanece igual?

---

ESTRATEGIA C | FÓRMULA CERRADA

Escribimos la suma en ambos sentidos:

S = 1 + 2 + … + n

S = n + (n−1) + … + 1

Al sumar columna por columna obtenemos n veces n+1:

2S = n(n+1)

---

FÓRMULA CORRECTA Y PSEUDOCÓDIGO

Por tanto:

S(n) = n(n+1)/2

No es n(n−1)/2. Esa expresión omite una cantidad equivalente a n.

Compruébenlo con n=1, n=5 y n=10 antes de programar.

ALGORITMO suma_formula(n)
  validar que n sea entero y n ≥ 1
  total ← n·(n+1)/2
  devolver total
FIN

El número de operaciones aritméticas no crece con n bajo este modelo.

---

CORRECCIÓN NO ES EFICIENCIA

Una estrategia puede ser:

• correcta y costosa;
• correcta y eficiente;
• rápida en una prueba, pero incorrecta para ciertos datos;
• matemáticamente correcta, pero vulnerable a límites del tipo numérico.

Evaluaremos estas propiedades por separado.

RUTA PYTHON: SI TU PAREJA ELIGIÓ PYTHON

def suma_iterativa(n):
    total = 0
    for i in range(1, n + 1):
        total += i
    return total

def suma_formula(n):
    return n * (n + 1) // 2

Identifiquen la correspondencia con cada línea del pseudocódigo.

---

RUTA MATLAB: SI TU PAREJA ELIGIÓ MATLAB

function total = suma_iterativa(n)
    total = 0;
    for i = 1:n
        total = total + i;
    end
end

function total = suma_formula(n)
    total = n * (n + 1) / 2;
end

TIPOS NUMÉRICOS Y DESBORDAMIENTO

La fórmula puede calcular pocas operaciones y aun así producir un resultado incorrecto si el tipo numérico no representa n(n+1).

Antes de usar entradas grandes, averigüen:

• tipo de dato;
• valor máximo;
• comportamiento ante desbordamiento.

IDEA QUE NOS LLEVAMOS

Comparar algoritmos exige declarar el tamaño de entrada, la operación básica y el modelo de costo.
